# Security Policy

## Supported Versions

Security patches and hardening updates for **DevGuard** follow the latest release line:

| Version | Supported |
| ------- | --------- |
| 1.7.x   | :white_check_mark: |
| 1.6.x   | :white_check_mark: |
| < 1.6.0 | :x: |

## Reporting a Vulnerability

Please **do not** open a public GitHub Issue for suspected security vulnerabilities (such as path jail bypasses, prompt injection boundary leaks, secret exposure, or rule/masker bypasses).

- **Preferred channel:** Report privately via **GitHub Private Vulnerability Reporting** / **Security Advisories** on the `OkyWoww/DevGuard` repository.
- **What to include:** Affected version/commit, steps or minimal reproduction input, expected vs. actual behavior, and impact assessment.
- **Response & disclosure:** Because DevGuard is maintained independently on a best-effort basis alongside day-to-day work, 
initial triage is typically aimed within a few days, with status updates provided as reproduction and fix verification progress.
Confirmed vulnerabilities will be patched before public disclosure, while reports that are out of scope, already fixed, or not reproducible will be explained clearly when closed.
